# Pilot 2026-07-01

## Claims
- A code-as-source wiki is viable for this repo using architecture + API + data-flow pages as the baseline.
- The most valuable initial coverage is chart workflow, backend API surface, and provider/sync behavior.
- Project-local wiki skills (`/wiki-ingest`, `/wiki-query`, `/wiki-lint`) plus prompt templates are sufficient to operate without helper scripts.
- Taxonomy calibration: keep top-level groups as `Architecture` and `Operations` for low-friction navigation.

## Evidence
- Chart orchestration is centralized in `frontend/src/components/trading/chart-workspace.tsx`.
- API surface is clearly segmented in `backend/app/api/analysis_routes.py`, `market_routes.py`, `stock_routes.py`.
- Provider and sync logic are explicit in `backend/app/fetch/downloader.py` and `backend/app/services/sync_service.py`.
- Wiki operations are implemented as project skills in `.cursor/skills/wiki-ingest`, `.cursor/skills/wiki-query`, and `.cursor/skills/wiki-lint`.
- Skill-triggered enforcement lives in `.cursor/rules/wiki-ops-enforcement.mdc` (`alwaysApply: false`).
- Prompt templates and policy details remain in `wiki/pages/manual-ops-prompts.md` and `AGENTS.md`.
